ByteTide 通知样式 Demo · 三选一

断开连接与串口热插拔通知的三种候选呈现。点击每个窗口下方的按钮触发；悬停通知可暂停倒计时，点 × 立即关闭，自动关闭 4.2s（实际实现建议：断开 6s、常规 2.8–3.2s，重连成功会自动收掉未过期的断开横幅）。

方案 A · 顶部居中横幅

存在感最强
从标题栏下方滑降，落在视觉中轴上，连接状态变化一眼可见；左缘 4px 语义色条 + 圆形图标位，不遮挡两侧面板。
入场 260ms cubic-bezier(.16,1,.3,1) 下滑 16px + 淡入 · 离场 180ms ease-in 上滑 + 淡出 · 进度条线性递减 · 堆叠补位 200ms

方案 B · 右上角卡片流

桌面原生通知感
从右侧滑入、右上角纵向堆叠（Windows 原生通知的对角位），完全不遮挡日志与图表；适合热插拔这类频繁但非致命的事件。
入场 240ms cubic-bezier(.16,1,.3,1) 右侧滑入 28px + 淡入 · 离场 160ms ease-in 右滑淡出 · 堆叠补位 200ms（移除中间一张试试）

方案 C · 底部中央升起

中轴 · 不遮日志尾部
从发送区上方升起，比右下角显眼（落在视觉中轴），又不挡日志滚动区；卡片语言与 B 同族。
入场 280ms cubic-bezier(.16,1,.3,1) 上升 24px + 淡入 · 离场 200ms ease-in 下沉 + 淡出 · 堆叠补位 200ms
实现说明（选定后落地）：样式迁移进 styles.css（全部走现有 token，双主题各一套值）；触发点不变（useTauriEvents 的 session-status）； 热插拔由前端对 port-changed 前后端口列表做 diff（应用启动首次事件只建基线不弹通知）； 设置弹层「通知」分组提供三个开关：连接状态 / 串口接入 / 串口移除，持久化 serialtool.notifications。 动画纪律：只用 transform/opacity、150–300ms、prefers-reduced-motion 时退化为淡入淡出。
